Implement auth: login with email + password (argon2), short-lived JWT access token containing only sub and session id, refresh token in an httpOnly secure sameSite cookie with rotation and server-side revocation, logout, logout-all, change password, CSRF protection for the cookie flow. Director must enable TOTP 2FA (setup, verify, login challenge). Parents log in with phone/email OTP (sender behind an interface, queue-based; OTP valid a few minutes, 5 attempts, invalidated when a new one is sent). AuthGuard is global and routes are protected by default; mark public routes with @Public(). AuthGuard loads the current user, isActive, roleKey and permissions from Redis/DB on every request (never from token claims) and rejects revoked sessions and deactivated users immediately. Apply the strict counters from the master context to login (5 failures per 15 min per account, 20 per 15 min per IP, escalating delay, no permanent lockout), OTP request/verify, password reset and refresh. Responses must not reveal whether an account exists. Seed script creates the first Director with a forced password change; refuse to deactivate or demote the last active Director. Include GET /me (user, roleKey, branches).
Done when: e2e tests cover login, refresh rotation, revoked session, deactivated user blocked on the next request, role change effective immediately, 2FA flow, lockout escalation and 429 headers.
