Build src/common.
1) PrismaService; a Prisma client extension that applies branch scoping to branch-owned models (clients, leads, appointments, invoices, expenses, attendance_records, rooms) using the request's allowed branch ids; a request-context mechanism (AsyncLocalStorage) carrying user, roleKey, scope, allowed branch ids and active branch; decorators @CurrentUser, @CurrentBranch, @Public, @Roles, @RequirePermission.
2) Global exception filter with one error format; global ValidationPipe (whitelist, forbidNonWhitelisted, transform); config module with validated env vars; versioned prefix /api/v1; Swagger at /api/docs; health endpoint; helmet, CORS allow-list, request size limits, trust proxy.
3) Pagination: helpers and DTOs for offset (page, pageSize default 20 max 100) and cursor (limit, cursor) pagination, the response envelopes from the master context, a sort-field whitelist helper with an id tiebreaker, and Swagger decorators for them.
4) Redis module and CacheService: namespaced keys, get/set with TTL, getOrSet, delete by key and by prefix, safe JSON serialisation, metrics for hit/miss.
5) Rate limiting: a global token-bucket guard on Redis (per user: capacity 40, refill 2/s; unauthenticated per IP: capacity 10, refill 0.5/s) using rate-limiter-flexible or an atomic Lua script, a @Throttle-style decorator for strict per-route counters, a service for lockouts with escalating delays, 429 responses with Retry-After, fail-open for general limits and fail-closed for auth routes, and an exemption for signature-verified webhooks.
6) A test helper that counts Prisma queries during a request so e2e tests can assert a maximum query count.
Done when: tests prove branch A queries never return branch B rows, pagination caps work, the cache invalidates correctly, a burst beyond the bucket gets 429 with Retry-After, and two users behind one IP do not affect each other.
